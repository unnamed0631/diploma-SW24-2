# Local testing & seed data

## 1. Start MongoDB

Any MongoDB 6/7 works. With Docker:

```bash
docker run -d --name bluvi-mongo -p 27017:27017 mongo:7
```

## 2. Minimal server `.env`

`server/.env` can stay tiny for local work — every third-party service is
optional and its feature degrades instead of crashing the server:

```dotenv
MONGO_URI=mongodb://127.0.0.1:27017/bluvi
PORT=3000
BASE_URL=http://192.168.1.8:3000          # LAN IP for device testing (not localhost)
SECRET_ACCESS_TOKEN=dev-access-secret     # required, must be non-empty
SECRET_REFRESH_TOKEN=dev-refresh-secret   # required, must be non-empty

# Optional
# REDIS_URL=redis://localhost:6379        # falls back to an in-memory cache
# GEMINI_API_KEY=...                      # AI chatbot / food / goals / plans
# FIREBASE_SERVICE_ACCOUNT=...            # image uploads (local fallback otherwise)
# FIREBASE_STORAGE_BUCKET=...
# SMTP_HOST/SMTP_USER/SMTP_PASS           # verification email
# FOODPLAN_SCRAPE_IMAGES=true             # Puppeteer food photos (slow)
```

`BASE_URL` is not cosmetic: seeded avatars/post images and locally uploaded
files are served as `${BASE_URL}/uploads/...`, so it must be the address the
**device** uses to reach the server. `EXPO_PUBLIC_API_URL` in `app/.env.local`
must point at the same host and port.

What happens when a service is **missing**:

| Service      | Missing-behaviour                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| Redis        | in-memory fallback cache, warning in the log                                                                                   |
| Gemini       | daily goals use a Mifflin-St Jeor fallback; `/chatbot`, `/auth/exercise`, `/auth/food/image` answer `503` with a clear message |
| Firebase     | uploads are written to `server/public/uploads` and served at `/uploads/...` (dev only; production throws)                      |
| SMTP         | `POST /auth/verify-email` answers `503`                                                                                        |
| Google/Apple | those sign-in buttons fail, email/password login still works                                                                   |

## 3. Seed the database

```bash
cd server
bun install
bun run seed
```

`bun run seed` is **destructive** (it clears users, posts, comments, goals,
completed days, chats and refresh tokens) and prints the credentials at the
end. It writes small placeholder images to `server/public/uploads`.

## 4. Run the API and the app

```bash
cd server && bun run dev
```

```bash
cd app
cp .env.example .env.local     # EXPO_PUBLIC_API_URL=http://<your-lan-ip>:3000
bun install
bun run start --clear          # --clear after changing EXPO_PUBLIC_*
```

The app assumes the API lives at `EXPO_PUBLIC_API_URL`; on a physical device
use your machine's LAN IP, not `localhost`. Port clashes are common (3001, 8081):
if something else already owns the port, either stop it or change `PORT` **and**
`EXPO_PUBLIC_API_URL` together.

## 5. Things worth clicking

- **Streak** (`Flame` button on Home) — calendar with completed days and
  achievements (Bat-Erdene unlocks "7-Day" and "14-Day" is in progress).
- **Blogs** tab — seeded posts, likes, comments, bookmarks.
- **Profile → … → Settings** — theme and language switches.
- **Chatbot** — only works with `GEMINI_API_KEY`; otherwise the stream reports
  "AI features are disabled".
- **Training** — "Your Daily Workouts" is fed by the seeded exercise plans.

## 6. Running the seed against a disposable database

Use a separate database name and port so you never touch real data:

```bash
MONGO_URI=mongodb://127.0.0.1:27018/bluvi_seed_test bun run seed
```

`SEED_MODE=true` (set by the `seed` script) also tells the server to skip the
streak-reset cron job, so a seeded test server never mutates streaks overnight.

## 7. Troubleshooting

| Symptom                                                    | Cause                                                                                                                                                      |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Login returns `500` / `SECRET_ACCESS_TOKEN is not defined` | `server/.env` has the key but **empty**, or the server was started before it was filled                                                                    |
| `MongoDB connection error` then exit                       | `MONGO_URI` empty, or Mongo is not running (`docker ps`)                                                                                                   |
| App spinner / network errors                               | `EXPO_PUBLIC_API_URL` port ≠ server `PORT`, stale LAN IP, or `localhost` on a device                                                                       |
| Changed `EXPO_PUBLIC_API_URL` but nothing changed          | `EXPO_PUBLIC_*` is inlined at bundle time — restart with `bun run start --clear`                                                                           |
| Images 404 / blank avatars                                 | `BASE_URL` does not match the address the device uses                                                                                                      |
| `Port in use`                                              | another process owns 3000 (or 8081); pick a free port and update both env files                                                                            |
| AI replies fail with `503`                                 | no `GEMINI_API_KEY` — expected offline; goals still fall back to local maths                                                                               |
| Streak does not advance                                    | all daily tasks must be completed; `POST /streak/increment` is idempotent per day                                                                          |
| Profile chart says "No daily history yet"                  | stats history is **device-local** and needs two recorded days for a line; change a stat (water, steps, a meal) and today appears as a dot immediately      |
| Timeline is empty                                          | only completed pose-tracking sessions are recorded so far — finish a Training test to create an entry                                                      |
| Notifications never arrive                                 | `expo-notifications` is a native module: rebuild the dev client, grant the prompt, and check the status line on the Notifications screen (web unsupported) |
| `Couldn't find a LinkingContext context.`                  | theming regression — CSS variables added after first render; see `docs/theming.md`                                                                         |
